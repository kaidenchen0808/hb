# 设计:代查任务状态指示 + 引用来源(消灭等待黑洞与出处缺失)

- 日期:2026-10-27
- 状态:设计已确认(brainstorm 逐段过审),待实现
- 范围:gateway(WS status 帧 + 代查 JSON 化 + prompt 解禁) + app(指示条 UI);v0.5.0 + 0.13.0

## 背景与目标

用户实测两大体感痛点:
1. **等待黑洞**——[lookup] 二段触发后聊天轮已结束,后台代查 1~4 分钟界面完全静默,不知她在查还是挂了
2. **无出处**——她联网查回的资料只有口语转述,没有网页/文档来源链接(豆包/千问标配)

## 方案一:任务进行中状态

```
转场回复(轮结束) → WS {type:"status", text:"她正在查资料…"}
  → app 输入框上方常驻指示条(呼吸动画 + ✕ 手动取消)
代查完成 → {type:"status", text:null} → 消失
失败/超时 → 状态帧带失败文案 → "查询失败了" 2s 后消失
```

- 复用 `/v1/ws` say 帧通道,新增 `status` 帧类型;轮询兜底(`GET /v1/notifications` 响应带 `activeLookup` 字段)。
- ✕ 取消:app 请求 → 网关 kill 代查子进程(复用 abort 基建)。
- V1 粗粒度(在查/完成/失败);多轮工具进度("正在搜索…/正在读网页…")后续增强。

## 方案二:引用来源(结构化,不信模型拼格式)

```
代查 claude 按约定 JSON 输出:
  {"result": "口语化结论…(可含 ![](url) 图片)", "sources": [{"title": "...", "url": "..."}]}
gateway 解析 → result 照常进 outbox 补说;sources 附在消息末尾:
  ──── 来源 ────
  1. [维基百科：刘德华](https://...)
app Markdown 链接渲染(零改动)
```

- JSON 容错:解析失败整段当 result、来源空——永不因格式丢内容。
- 三处 prompt 解禁(代查为主):正文口语化不带链接,但 sources 字段给出处;URL 必须工具真实抓到,禁止编造;上限 5 条。
- 来源不进 TTS(她口头只说结论,URL 是给眼睛的)。

## 改动面

| 端 | 改动 | 量级 |
|---|---|---|
| gateway | status 帧推送(开始/结束/失败) + 轮询带 activeLookup + 代查 JSON 化 + prompt 解禁 + 取消端点 | ~120 行 |
| app | WS status 解析 → lookupActive 状态 → 指示条(呼吸动画+✕) | ~80 行 |
| 来源渲染 | Markdown 链接管道现成 | 0 |

## 测试与验收

**单测**(gateway):status 帧时机;代查 JSON 容错(纯文本/markdown 包裹/sources 超限);来源不进 TTS。
**手测**:指示条即时出现/消失;补说带可点来源;✕ 取消真终止;超时失败文案;TTS 不念 URL。
